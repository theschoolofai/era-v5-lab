## Why a TSAI run

`dedup.py` is small: the local run takes seconds and 1 GB. The run is still needed because source-priority rule 2 (prefer the copy with a url) reads each matched copy's `url` from the cleaned parts, which are on TSAI's host only. Without them the number of removed documents is the same, but in ties a different copy can be removed. TSAI filters the cleaned data with the exact remove list, so the list must come from the run with urls. This is not a cleaning request: it reads the overlap outputs and writes a list; it changes no data.

Run it in the same working tree as the overlap job, after that job's outputs are in `out/overlap/`. `dedup.py` stops with an error, before writing anything, if:

columns of parts that hold a matched document.

## What the run does

It first sets aside the matches between the empty documents of the overlap run (no shingles: cleaning emptied them
without dropping them; they are listed in `empty_documents.csv`, not removed; see `dedup/README_dedup.md`). On the 5 Nov
run these were 21 matches between 7 documents. It then joins the other qualifying H1/H2 matches (2,690 on the 5 Nov run)
into clusters and applies `source_priority_v1.md` to each:

| Rule | Survivor |
|---|---|
| 0 | Every held-out copy; train copies of a held-out document are removed. Held-out ↔ held-out matches are reported, not removed |
| 1 | A copy whose pack has a usable licence. All 38 packs are treated as usable (`default_licence_usable: true`) for this experiment only (TSAI, 12 Nov); `code-js-ts` and `ind-hi-hplt` are not verified, and G10 owns the final licence decision |
| 2 | A copy with a url |
| 3 | The longer copy |
| 4 | The pack ranked first in `pack_order` (Data A's 13 packs in `clean.py` order, then Data B's 25 alphabetically, as approved by TSAI on 10 Nov), then the lowest `(split, part, doc_id)` |

The cross-pack pass is applied (`cross_pack: true`), as decided after the overlap job. The harm check reads `teams/01-data-a/gold/` and `teams/02-data-b/gold/`; on sample v0 it reports `not_testable`, since the gold comes from the week-1 diagnosis packs. The method and every output field are described in `dedup/README_dedup.md`.

## Expected differences from the local run

The local runs below used the 5 Nov overlap outputs, so their counts are not the expected values for this run. Once the rerun's overlap files are returned, `dedup.py` is run locally on them without urls, and its counts are added here before approval.

The total removal count, the rule-0 removals and the held-out result do not depend on urls, so TSAI's run should match those values from the local run. Per-pack, per-stage and H1/H2 log counts can change when rule 2 changes the survivor, especially in cross-pack groups; review those differences rather than requiring equality. Only clusters decided locally by rule 3 or 4 (770 and 287 on the 5 Nov outputs) can be decided by rule 2 instead, which changes which copy survives in those clusters, not how many are removed. `empty_documents.csv` does not depend on urls. If every matched copy has a url, rule 2 breaks no tie and the survivor choices match the local run. If url availability differs within a group, the remove list, group roles and decision log may differ; heldout_duplicates.csv and empty_documents.csv remain unchanged for identical overlap inputs.
