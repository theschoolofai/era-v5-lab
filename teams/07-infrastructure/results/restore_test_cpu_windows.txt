Notes:
- Equal bits across different machines are not a goal of this test. The test compares run A with run B on
  the same machine and the same process count only. A different number from the Linux run is not a failure.
- The losses differ in the last digits from the Linux run in results/restore_test_cpu.txt, and between 1 and
  2 processes. restore_test.py fixes torch.set_num_threads(1), so the difference most likely comes from
  different CPU math kernels on different hardware. The Linux file does not record its CPU model, so this
  reason cannot be checked against it yet.
- The 2-process run printed one pair of c10d warnings at each of the three launches (run A, and both launches
  of run B):
    [W ... socket.cpp:764] [c10d] The client socket has failed to connect to [<hostname>]:<port>
    (system error: 10049 - The requested address is not valid in its context.).
  restore_test.py sets MASTER_ADDR=127.0.0.1 and binds the port on 127.0.0.1. The run passed with that
  setting, and the warnings appear anyway. They are warnings, not errors: a Windows user can ignore them.
  The machine name is replaced by <hostname> here.
- The gloo use_libuv error that can appear on Windows did not appear, so USE_LIBUV was not set.
- Python 3.13 was used, the same minor version as the Linux run, so that the pinned versions in
  teams/04-ke2/src/requirements.txt install from ready-made wheels.
